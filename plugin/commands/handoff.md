You are creating a **delulu handoff**: a self-contained, token-efficient capture of THIS session so a fresh Claude Code session continues exactly where this one stops, with the user never having to re-explain context.

**STEP 1. Let delulu read the repo.** Run this EXACT command and read its output (it writes a draft handoff folder and prints what it read from the real repo and disk at capture, not your narration):

```
node "${CLAUDE_PLUGIN_ROOT}/hook/cli.mjs" handoff
```

Note the folder path it prints (`.delulu-handoff/<ts>/`). The block headed "What I checked myself" is delulu's own reading and is FINAL, never edit it.

**STEP 2A. Sort the rulings, BEFORE any other question.** Open `.delulu-handoff/<ts>/payload.md` and look for the `CARRIED FORWARD` comment. It holds the rulings the user locked in earlier sessions, already session-qualified, pre-sorted by delulu into *still holds*, *no signal* and *probably spent*. **It is ABSENT on the first capture in a repository**. There is no earlier handoff to carry from, so if it is not there, nothing has gone wrong: go straight to the rulings THIS session produced. Where it is there, read it in full; it is the instruction, and what follows here is a summary of it.

**Carrying is not the default.** Every carried line goes to exactly one of four places, and only the last keeps it:

- **ALREADY ENFORCED**, a test or a command file already holds it. Drop it, and name what holds it.
- **COULD BE A CHECK**. Drop it, and write the check. That is the real work; the sorting is not.
- **WAS STEERING**. Direction given in the moment, spent the moment it was acted on. Drop it.
- **CANNOT BE EITHER**. Keep it, and say WHY on the line itself, in this exact form:
  ``- <rule>. `ref`: "their words", cannot be a check: <why>``

That reason is required, not decoration. A line kept under "What holds until you say otherwise" without a `, cannot be a check:` on it is NAMED back at you when you seal, one finding per line. Judgement about risk and preference about taste are the honest cases; "it feels important" is not one.

Those four are the question asked of a STANDING RULE. A carried line that is still live but was never one. Delulu's *no signal* and *probably spent* groups. Goes under **"What you decided this session"** instead, where it dies at this session's boundary and needs no reason.

Put the sort to the user with AskUserQuestion, recommended-first, in batches. Delulu's grouping is read off the words on each line and is a GUESS, so the user decides. A kept line is copied VERBATIM, ref and quote intact. Delete the `CARRIED FORWARD` comment once you have been through it: leaving it in the sealed file is read as an interview that never happened, and delulu reports every constraint that session locked as still open. Do the same sort for the rulings THIS session produced. Ask as many rounds as the session needs.

This runs first deliberately. Sorting is cheap next to the prose, and the end of a session is when your context is at its most degraded, so spend it on the answers that outlive the session. A line nobody sorts is not a failure: leave it in "What you decided this session" and it behaves exactly as every carried decision did before the two blocks existed.

The user's authority is over the RULE, not over where it lives. Nothing here ages out, and you never decide on your own that a constraint has stopped applying, only the user revokes one. Building a rule into a test and dropping the line is not revoking it: the constraint is now enforced instead of described, and it costs the next session nothing to read. What you must never do is let a rule quietly stop being carried with nothing enforcing it and nobody told, that is the exact defect these two blocks exist to fix. So take every drop to the user, and name what you dropped, and why, under "What I made of it (unchecked)".

**STEP 2B. Interview the user RELENTLESSLY** to fill only the gaps delulu cannot capture. Use the AskUserQuestion tool, recommended-answer first, in batches, until there are ZERO context gaps. Cover at minimum:
- **Where we left off**. Where the conversation actually stopped. delulu may have written a verbatim **What you said** block into the checked zone (the user's messages, in order, long ones shortened; when present, its own heading says whether it carried every one or had to leave some out on a very long session). It is OMITTED when the user's only turn was a boilerplate opener, so do not assume it is there, and where it is, do NOT re-paraphrase those quotes. "Where we left off" is your *interpretation* anchored to them: the unfinished thought, the intent behind the words, what you were mid-discussion. Write it as a live continuation, not a status line. (You already lived this session; confirm/sharpen rather than re-asking what you know.)
- **Start here**. Exactly ONE action, with a **searchable anchor** (the function or the exact string to grep for, not `file:line`, line numbers rot: any edit above the line moves it, and a stale ref lands on unrelated code without saying so), **and the reason it is first**. Not a list. A handed-forward task list is the shortest-lived thing in a handoff (usually stale on arrival, and it anchors the next session to a plan the user may have already moved past), while the *reason* survives, a successor who knows why can re-decide what.
- **What holds until you say otherwise**, the rules that OUTLIVE this session: what the user has locked and has NOT revoked. Same evidence standard as the block below, and the same citation form, a rule with no `L<n>` behind it does not belong here any more than a decision does, and a rule is the more dangerous of the two to get wrong, because it arrives in a session that cannot remember whether it was ever true. A rule locked in an EARLIER session keeps its ORIGINAL session-qualified ref, and a line kept here must also carry its `, cannot be a check:` reason (STEP 2A). This block is what a permanent constraint needs to survive: the block below it is emptied at every session boundary, so a standing rule filed down there stops being carried without anyone ever deciding it should. Nothing here ages out or expires quietly. **Leave it EMPTY if nothing stands yet**, delulu reads an empty rules block as the true statement it is and does not count it as an unfinished section; inventing a rule to fill it is worse than leaving it blank, because it will arrive in every later session wearing a citation.
- **What you decided this session**. What the USER locked this session and will be SPENT when it ends: a call about one file, one commit, one task. This block is not carried forward, which is the whole point of it being separate. If a line here would still be true in a month, it belongs above instead. One line per decision, **each line ending with the `L<n>` line-ref where they said it, followed by their own words from that line**. E.g. ``- Free models only, never a paid API. `L412`: "i dont want a paid api"``. The refs come from the "What you said" block, when delulu wrote one. If it is not there, you have no citable lines and nothing belongs under "What you decided". Quote a few words verbatim from the line you cite. A line rendered as `**you stopped the agent here**` is an interrupt anchor, NOT something the user said. Citing it is reported as a fabrication, so cite the line carrying their words instead. If you cannot point at the line where they said it, it does not go here. delulu re-checks this at finalize and again at resume, and prints any line that cites a place they never spoke, quotes words they did not say there, or cites nothing at all, so an uncited or mis-cited "locked decision" is visible to the user, not silently authoritative. What the check cannot judge is whether your summary in front of the quote is a fair reading of it, so let the quote carry the decision.  **Prefer words they TYPED.** A pick of an option YOU wrote and marked "(Recommended)" is the weakest citation there is, the sentence, the framing and the nudge are all yours, and quoting it back as their ruling is you quoting yourself; delulu now reports such a line as "rests on words the AGENT wrote" instead of as verified. This is the commonest way a decision block goes wrong, and nothing in the interview pushes back on it, so it is on you to catch. A pick of a NON-recommended option is different and still counts, choosing against your recommendation is the user overruling you. **Carrying a decision forward:** a constraint the user locked in an EARLIER session is still locked, and it keeps its ORIGINAL ref, session-qualified, ``- Continuity is the product. `2026-08-17T20-01-36:L92`: "continuity is the product"``. Where the stamp is the handoff folder it came from. delulu resolves it against THAT session's own record, and prints it back to the user by that handoff's name rather than its stamp. Never re-point an old decision at a line in this transcript: that line holds someone else's sentence, and the check reports it as a fabrication.
- **What I made of it (unchecked)**. Your own conclusions, inferences, and judgement calls. These are genuinely useful and belong in the handoff; they simply are not rulings. Never promote one into either rulings block to make it sound settled, and least of all into "What holds until you say otherwise", where it would be re-served as settled law to every session after this one.
- **What else went wrong**. Check the payload first. IF delulu wrote a "What broke" block, it holds the MAIN AGENT's tool errors from this session, each clipped to 220 characters and capped at 12. Do not re-ask the user for those. But that block is ABSENT whenever nothing errored, and it NEVER contains a subagent's errors. So ask for everything it cannot hold: approaches that ran cleanly and were still wrong, dead-ends abandoned before anything errored, a subagent that failed, and what was tried.

Ask ONLY what delulu can't know (intent, decisions, what's next). The facts (files, commits, repo state) are already captured.

**STEP 3. Write the answers into the draft.** Edit `.delulu-handoff/<ts>/payload.md`, replacing each `<!-- delulu:fill ... -->` placeholder with the user's answers. You do **NOT** need to touch `context.md` or read any subagent transcripts: delulu already extracted each subagent's **verbatim final result** into `context.md` (zero tokens, no paraphrase) and put a one-line gist of each into the payload. Only open a raw transcript if the user asks for reasoning the verbatim final doesn't already carry.

**STEP 4. Reseal the checked blocks, then confirm.** Everything delulu wrote was captured BEFORE the interview, and the interview is where the user says the most, so by now the repo may have moved (a commit, more edits) *and* they have sent messages that the draft cannot contain. Re-read it all with the folder name from STEP 1:

```
node "${CLAUDE_PLUGIN_ROOT}/hook/cli.mjs" handoff --restate <ts>
```

This re-reads every block delulu writes itself, "What I checked myself", "What you said" and "What broke", and leaves **every section you wrote untouched**. It may also print a short "these lines may be in the wrong block" question: delulu re-reads your two rulings blocks and asks about any line whose wording disagrees with where you filed it. Nothing is moved and nothing is blocked. Take it back to the user if it matters, or say why the sort is right. Run it on the folder THIS session created: it refuses a handoff captured from a different session, because resealing that one would overwrite its record of what the user said. Then tell the user the handoff is ready, and that in a fresh session they just type `/delulu:resume` to continue. Nothing else, no pasting, no re-explaining.

**STEP 5. Name the handoff.** Give it a short, memorable name, the way you would title a chapter, not summarise a report. Three to six words, lowercase, specific to what actually happened: "dead weight, live bugs", "arrived cold", "the same mistake, three times". This is what the user sees in `delulu resume --list` and how they load it, so it has to mean something to them a month from now. Do not ask them to name it. Offer yours, and take a correction if they give one.

```
node "${CLAUDE_PLUGIN_ROOT}/hook/cli.mjs" handoff --restate <ts> --name "your short name"
```

An unnamed handoff is listed by its date instead, which is still loadable but tells the user nothing about what is in it.

Never invent facts. **Compact, don't summarize:** keep conclusions, decisions, error→fix pairs, file paths, and any rule/constraint *verbatim*; never echo raw tool output or git/disk facts (the block delulu checked holds those as of capture time; resume replays them unchanged and does NOT re-check them, so treat them as a snapshot). Write "What else went wrong", "What holds until you say otherwise" and "What you decided this session" as **one checkable fact per line**. Keep the recent / unresolved thread high-fidelity; compress the early, superseded turns. Capture everything load-bearing first, then cut the lowest-value lines to stay tiny, never blind-truncate. The payload must be rich enough that the next session needs nothing else, yet a fraction of the raw transcript's bytes, that ratio is the product.
