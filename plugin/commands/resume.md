Run this EXACT command (pass through whatever the user typed after the command) and read its FULL output:

```
node "${CLAUDE_PLUGIN_ROOT}/hook/cli.mjs" resume $ARGUMENTS
```

Then act on what the output is:

- **If it's a LIST of handoffs** (the user ran `--list`): show the list to the user and STOP. Ask which one to load (`delulu resume <name>` — each handoff is listed by the name its session gave it, or by its date if nobody named it; either is what you pass back, never the folder timestamp). Do NOT auto-load or continue anything.
- **If it's a LOADED handoff** ("What I checked myself" + "What holds until you say otherwise" + "Where we left off" + "Start here" + "What you decided this session" + "What else went wrong" + "What I made of it (unchecked)", plus "What you said" and "What broke" when delulu had anything to put in them — a handoff sealed before the rulings split in two has a single "What you decided" instead of the two blocks, and one sealed by a session with no standing rules has an empty rules block, which is a true statement and not a fault — "What you said" is omitted when your only turn was a boilerplate opener, "What broke" whenever nothing errored): read **"Where we left off"** FIRST — it's the live conversation where you stopped. **Open by CONTINUING that conversation in your own voice** ("we left off worried about X — picking that up"), NOT by reciting the blocks back at the user. Then **drive forward via the AskUserQuestion tool** — put your first question (the verdict on "Start here", or any genuine gap) to the user as AskUserQuestion options, recommended-first. **NEVER end the turn with a bare plain-text question or a flat stop** — every resume hands the user clickable next steps.
  - **If the first lines say the handoff was too big to send whole, or didn't fit at all, this output is NOT the whole handoff.** The payload exceeded one Bash output (the harness silently replaces anything over ~30KB with a 2KB preview), so delulu left out the blocks it names there rather than let the pipe cut wherever it landed. If it named the blocks it left out, **open `.delulu-handoff/<ts>/payload.md` and read those headings** — not the whole file, which you already have almost all of. If it says nothing fitted at all, read the file in full: that file is the handoff and this output isn't. Either way, never infer that a block named in the notice was empty or unimportant.
  - **Then read "What holds until you say otherwise".** Those are STANDING RULES the user locked and has not revoked — they carry across every session until the user retires one, and they frame everything you read after them, so read them before the rest of the notes and treat them as still in force. Two things they are not. They are not aged out by time: nothing in that block expires quietly, and "it looks old" is not a revocation. And they are not stronger than they read: a rule that stopped being true still arrives wearing a verbatim citation, which is exactly what makes it outrank a fresh judgement, so if one contradicts what you can see in the repo or what the user is saying now, say so plainly and let them decide — never quietly drop it and never quietly obey it. Only the user revokes a rule. When you write the next handoff, carrying a line on is not the default: `/delulu:handoff` asks of every one whether a test or a command file could hold it instead, and a line that stays keeps its ORIGINAL session-qualified ref plus the reason no check could hold it.
  - **Read "What you said" first.** It is the user's own voice — the messages and decisions they gave last session, verbatim, in order, extracted by delulu with `L<n>` line-refs (the block's own heading says whether it carried every one). That block is what makes this a continuation rather than a briefing; read it before the agent-written prose, and let it set your understanding of what they actually want.
  - **Provenance — do not launder unchecked notes into confident truth:** "What I checked myself", "What you said" and "What broke" are delulu's own reading ("What I checked myself" is a snapshot from capture time, not re-checked now). Lines under **"What holds until you say otherwise"** and **"What you decided this session"** are only as good as their `L<n>` citations — delulu re-checks them at load and prints any that don't trace to something the user said; treat those as the agent's opinion. A line delulu flags as resting on "words the AGENT wrote" is one where the user pressed a button the last agent had captioned and marked "(Recommended)" — real assent, but not their words, so do not restate it as their ruling. A line whose citation names an earlier handoff was carried forward and re-checked against THAT session's record — it is still locked, so do not re-litigate it; if the next handoff carries it on, it keeps that same qualified ref rather than being re-cited to this session. **"What I made of it (unchecked)"** is not proven at all. "Where we left off" and "Start here" are the prior session's *agent recollection* and can be wrong or over-optimistic. Before you assert any load-bearing claim as lived fact — especially "committed / pushed / done / tests passing" — cross-check it against what delulu actually read. If the note and the repo disagree (e.g. the note says "pushed" but the checked block shows a dirty tree / unpushed commit), surface the gap to the user as a calm heads-up ("the note says X, but the repo shows Y — your call"), never assert past it. You may still continue in-voice; just don't present an unchecked note as something delulu proved.
  - Treat the handoff as full context: the user must NOT have to re-explain anything, and you must never re-ask what the handoff already answers. The deep context file (`.delulu-handoff/<ts>/context.md`) holds the distilled subagent findings — open it if the payload is insufficient.
  - **Retrieval backstop — recover the real reasoning, don't trust the summary blindly:** "Where we left off" and both rulings blocks are the prior session's *unchecked* summary. `.delulu-handoff/<ts>/index.md` is a line-ref MAP of the prior session. Whenever a decision/claim is load-bearing or you doubt it, open the raw transcript (path in the map) and **Read around that `L<n>` to recover the exact verbatim reasoning** before you act or assert — cheap, and it's the ground truth behind the summary. (Transcript events are large — Read a SMALL window, a few lines via offset+limit, not 30+, or you'll hit the read limit.) This is how you carry the prior session's *understanding*, not just its facts.
- **If it says there's no handoff** (or no match): tell the user plainly and proceed normally.

Never invent or assume the contents — only act on what the command actually printed.
